## 1. Exported support / confidence combinations and column definitions

Per 1 km sinusoidal cell and UTC day, for each sensor (Aqua MYD14A1.061, S-NPP VIIRS VNP14A1.002):

- `land` = QA bits 0-1 == 2 (binary `10`)
- `fire` = FireMask in {7, 8, 9} AND land
- `fire_nh` = FireMask in {8, 9} AND land
- `usable` = (FireMask == 5 OR fire) AND land

Exported columns (sums over the block footprint and the period):

| Column | Definition |
|---|---|
| `D_aqua`, `D_viirs` | cell-days with `fire` |
| `O_aqua`, `O_viirs` | cell-days with `usable` |
| `D_aqua_nh`, `D_viirs_nh` | cell-days with `fire_nh` |
| `O_common` | cell-days `usable` for Aqua AND `usable` for VIIRS, same cell, same UTC day |
| `D_aqua_common`, `D_viirs_common` | cell-days with that sensor's `fire` AND `O_common` |

Combinations:

| Variant | Support | Policy | Status |
|---|---|---|---|

## 2. O_nh, common-support pairing, footprint denominator

- **O_nh (own support only):** `O_nh(s) = O(s) - (D(s) - D_nh(s))`. This removes the sensor's
  own class-7 cell-days from the denominator. Class 7 is treated as not observed, never as an
  observed absence. The other sensor plays no part. Consequence: `O_nh - D_nh = O - D >= 0`.
- **Common pairing:** same native 1 km cell (both products share the MODIS sinusoidal grid,
  tiles h/v of 1200 x 1200) and the same UTC day of the daily products. The cell-day is
  `usable` for both sensors. It is computed cell by cell before any summing. There is no
  spatial or temporal matching window.
- **Footprint denominator N_fp:** the number of 1 km sinusoidal cells whose centre lies inside the
  FAO GAUL 2015 level 1 polygon, with multi-part features dissolved by ADM1_CODE. It is a fixed
  count per region. It includes inland water. It is used only in the O screen and in coverage,
  never in a rate.
  **Caveat:** the value in the presence list (CA 478,430; BC 1,107,341) must be re-checked against
  the cell-level footprint of the NASA-direct run. Polygon edges must be densified before
  projection to the sinusoidal grid. If the value differs, P2 revises the list and its hash.

## 4. Day-level data and what must stay unavailable

**P2 position:** day-level data (file presence per day for both sensors) are sufficient for a
**provisional development calculation**, provided that:

1. Every output carries `footprint_evidence = day_level` and the label `provisional`.
2. The screens, variants and month rule used are registered (dated, with SHA) before the
   calculation runs. Otherwise any later change to them would be made after seeing 2016-2018
   outcomes. Unfrozen values may still be changed later, but only with a written reason that
   does not depend on the outcomes.
3. O-screen results using N_fp are marked provisional until N_fp is re-checked (point 2 caveat).

**Must remain unavailable until cell-level footprint evidence is verified by P1:**

- footprint status `complete` (stays `unverified`);
- `comparison_eligible = true` and `paired_comparison_eligible = true`;
- any final (non-provisional) factor and any stable or unstable conclusion label;
- harmonized rates shown as results, unusual or critical labels, and critical-week rankings;
- coverage-based states other than `unverified` (the 0.99 versus 1.0 tolerance is not decided);
- any input to the P5 sealed evaluation.
