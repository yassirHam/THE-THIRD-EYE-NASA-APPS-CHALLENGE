**States per sensor and period:**
- `complete`: all expected days present, all tiles present, coverage >= C_MIN.
- `partial`: at least one day present, with one or more reasons `period_clipped`, `missing_days_or_tiles`, `low_processed_coverage`.
- `unavailable`: no day present, reason `no_file` or `sensor_not_operating`.

## 2. Scope of "both sensors complete" (Q2)

- **Only paired MODIS/VIIRS comparisons** require both sensors `complete`
  (`comparison_eligible = state_aqua == complete AND state_viirs == complete`).
- **Aqua-only historical comparisons** (2002 onward, including all pre-2012 periods) need only
  `state_aqua == complete`. There is no harmonization before 2012.
- **Cross-era comparisons** (harmonized VIIRS target vs Aqua baseline) need the target period
  `complete` for VIIRS and each baseline period `complete` for Aqua. Each sensor is judged on its own state.

## 3. Missing files in the middle of the record (Q3)

  shown as incomplete data, never as zero fire. Final display rule: P4/P1.

## 6. Evidence for D <= O (Q6)

- **Masks:** land = QA bits 0-1 == 2. D = FireMask 7-9 on land. O = (FireMask 5 or fire) on land.
  Fire is a subset of usable, so D <= O for each cell-day.
- **Common support:** D_common = fire AND common, where common = usable in both sensors on the same cell and day.
- **nh policy:** O_nh = O - (D - D_nh). Hence O_nh - D_nh = O - D >= 0.
- **Code:** `pipeline/masks/firemask.py`, `pipeline/grid/accounting.py`, function `masks` in
  `notebooks/AFTERIMAGE_EE_V2.ipynb`.
- **Tests:** `tests/unit/` (123 passed). They cover every FireMask class, water and coast cells,
  empty days and sum-before-divide. Codex reviewed them and found no rule mismatch.
- **Data checks:** monthly export, 64 blocks, 16,512 rows, 2020-2021 excluded. 0 rows with any of:
  - D > O;
  - D_common > O_common;
  - D_nh > D;
  - O_common > min(O_aqua, O_viirs).

  Source: `check_report_monthly.json`. The weekly pipeline also checks O <= P.
