## 3. Answers to the P2 items in `handoff/escalations/P1/P1-P2-decisions-batch-r1.md`

**Coverage minimum C_MIN (P1 + P2, line 15).** P2 proposes 0.99, with disclosure of `coverage`
and `unprocessed_cell_days = N_fp x days_with_file - P`. The alternative is 1.0. The choice is
P1's. Until P1 registers a value, the contract must fail closed: no period may be `complete` on a
coverage tolerance, and `coverage_status` stays `unverified` while cell-level evidence is absent.

**Partition boundary for periods wholly inside the sealed window (P2, line 22).**
`partition_boundary` applies only to a period that crosses a partition boundary. Its days on the
open side are kept, so it is `partial`. A period lying entirely inside 2020-2021 is never read or
emitted by P2. In the contract it must be sealed / excluded, with no values and no
`partition_boundary` reason. It must not be shown as missing data or as `unavailable` with
`no_file`.

**Coverage reference code `pipeline/grid/coverage.py` (P2, line 23).** This file does not exist yet.
The current reference implementation is cell 9 of `AFTERIMAGE_weekly_NASA_direct.ipynb`:
footprint per tile, presence of all expected tiles per day, `P`, `coverage = P / (N_fp x
days_with_file)`, states and reasons. P2 will port it to `pipeline/grid/coverage.py`, with
synthetic unit tests, and report the commit SHA. Until then, the contract must not cite it as
existing code.

**Cell-level footprint evidence (P2, line 24).** In progress. The NASA-direct run was validated on
a one-week dev test (2019): 15 tiles, D <= O and O_common <= min(O_aqua, O_viirs) hold. The full
run (2016-2019 first, then 2002-2015 and 2022-2025, never 2020-2021) produces in
`AFTERIMAGE/nasa_direct/`:

- `run_log.txt`;
- `tile_years/*.granules.json` (source granules per tile-year);
- `report_weekly.json` (versions, footprint N_fp per region and tile, states, coverage, check
  issues, `sealed_years_read` = []).

Footprint status stays **unverified** until P1 checks this evidence.
