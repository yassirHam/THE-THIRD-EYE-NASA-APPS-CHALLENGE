## 1. Should missing calibration evidence be a separate state from missing observation support?
- **Fact:** in `tests/science/test_stage_a_invariance.py` `check_applicability` (lines 124-130), once O >= min_support, a missing (`None`) or unrecognised calibration-check status returns `missing_required_support`. That is the same label used for missing observations.
- **Plan:** Section 8B separates "Not enough usable evidence" (required observations *or checks* missing) from "Calibration check failed". It does not say whether a missing check and missing observations need different internal states.
- **Options:**
  - A: keep `missing_required_support` and add a reason field naming which is missing.
  - B: add a separate state for a missing calibration check.
  - C: B, and an unrecognised status (e.g. a typo) raises `ValueError` instead of becoming a status.
- **Recommendation:** C. The name should be chosen together with P4 (contract 1.1.0 has four applicability states) and P1-A (which uses `insufficient_evidence`); see escalation `P1-A-001-r3` item 2.
